# Transcription pipeline

Full history: docs/decisions/accuracy-vocabulary.md and docs/decisions/text-formatting.md

- Parakeet is the primary English engine. The upgrade pass is LLM `context_fix` only.
- A CRM name may not change a number the user said. One spoken word may not become a multi-word CRM name. "like" is a function word to the managed tier.
- Voice isolation was measured and deliberately not built. Do not build it without new measurement.
- A regression fixture may not read from the rolling `history.json`.
- Sentence Endings governs the stop the engine writes. Spoken lists must not fire on ordinary speech. Refine keeps what was said and its exact spacing.
- `_update_context()` is called with the **best available** result only (Parakeet final / whisper accurate / LLM-fixed), never the whisper fast-model result — so the rolling context always reflects the highest-quality transcription
- `context_fix()` validates word count (with small tolerance) before accepting the LLM result — rejecting additions/deletions keeps output exactly what the user said
- The pre-roll seed may carry **silence** freely and **speech** only under the rules in `_seed_cut_index()`. It exists for the gap between deciding to speak and the key arriving, nothing more: a warm mic that hears the room is the design, a warm mic that types the room is the bug. Never widen `_SEED_RUN_MAX`, never cut inside a run, and never delete the region instead of overwriting it — each of those is a shipped defect, pinned in `tests/test_seed_trim.py`
- `_vad_clip()` must never trim the HEAD or the TAIL of a clip — `_VAD_EDGE_KEEP` exists because Silero's onset estimate is unreliable for quiet speech and the user's own first and last words live exactly there. Lowering it re-opens the "it's not getting my first word" bug; removing the `if not chunks: return None` veto re-opens noise-only hallucination. Both directions are pinned in `tests/test_vad_edge_keep.py`
- `disfluency.destutter()` must stay INSIDE both engines' `_post_process`, right after `hallucination.clean` — that is the only point every path (batch, committed chunk, live caption, upgrade) flows through. It may only ever DELETE a token, never reword or reorder (bar lowering a restart's capital on a function word), and only in the three shapes it pins: a non-inflectional prefix fragment, a double from `_DUP_COLLAPSE`, or one copy of an unfinished 2-4 word phrase repeated exactly (`_is_phrase_restart`). It also runs once over the assembled dictation in app.py (chunk joins); that second call is idempotent and must stay skipped under Live Typing. The common-word list and the inflection guard are BOTH load-bearing (drop either and "the theory"/"car cars" get corrupted); the collapse set deliberately excludes emphatic/grammatical doubles ("very very", "had had"). Adding an abbreviation-fragment to `_COMMON_WORDS` silently disables the feature for that word. Both directions pinned in `tests/test_destutter.py`, including a corpus regression test
- **A term list may only reach a DECODER PROMPT if a human reviewed it.** `_get_prompt_hotwords()` (whisper) carries the user's own vocabulary only; `_get_hotwords()` (Parakeet, casing-only post-pass) may carry the managed/CRM set. Never merge the two back together: faster-whisper puts `hotwords` in the same token slot as previous-transcript context, so anything in that list can be emitted as speech nobody said. A wrong correction mangles a word the user did say; a wrong prompt invents a sentence they did not
- `hallucination.clean()` must stay INSIDE both engines' `_post_process`, never at a call site — that is the only point every path (batch, streaming chunk, live caption, upgrade pass) goes through. Its thresholds are load-bearing in both directions: raising `_MIN_RUN`/`_PURE_RUN` lets decoder loops through, lowering them rewrites real emphatic speech. Periodicity is found token-by-token, never unit-by-unit (a unit-aligned scan locks onto a shifted phase and strands a dangling fragment)
- The `_transcribe_lock` in `Transcriber`/`ParakeetTranscriber` serialises all transcription calls on a single model instance — do not call `transcribe()` concurrently on the same object
- `homophones.fix()` runs once on the ASSEMBLED dictation in app.py (after destutter, before spoken commands), never inside an engine and never under Live Typing. Every rule needs context on BOTH sides of the word and only spaces between the words of a shape. Adding or widening a rule means adding its legitimate readings as must-not-fire cases in `tests/test_homophones.py` and re-running a large prose corpus: a wrong correction changes what the user said.
