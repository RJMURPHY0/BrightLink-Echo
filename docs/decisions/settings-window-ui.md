# Decisions: Settings Window Ui

Moved verbatim from CLAUDE.md on 2026-09-29. Add new decisions as a dated entry at the bottom. 

- `2026-07-28` — Settings/Hotkey ghost fix made STRUCTURAL (v1.6.36). The duplicated-card ghost returned because every heal (RedrawWindow 0x181 per scroll step / per tab raise) is asynchronous at Tk level — Tk queues expose events and paints later, so a heal is a race it can lose. Root causes removed instead: (1) Settings and Hotkey tabs scroll on `ScrollPane` (place()-moved content frame; nothing ever bit-copies pixels, so a stale duplicate cannot exist) — never rebuild them on Canvas + create_window; (2) inactive dash tabs are UNMAPPED via grid_remove, not just lowered — an unmapped window has no pixels to bleed through (the old "grid_remove comes back black" note applied only under WS_EX_COMPOSITED, which stays removed). ScrollPane duck-types the Canvas scroll API so the shared wheel/scrollbar/scrollregion machinery is untouched; History keeps its native-canvas renderer. Guarded by `tests/test_scroll_pane.py` (behaviour + source-level invariants). Login fields went dark (`#141414` bars) — the near-white bars read as white boxes on the sign-in page.

- `2026-08-06` — Login→dashboard ghost, the remaining mechanism (v1.6.47). v1.6.38 moved the resize OUT of the WM_SETREDRAW freeze but never healed the resize itself: `RDW_UPDATENOW` only VALIDATES Tk's update region (Tk turns WM_PAINT into a queued Expose and draws on a later mainloop spin), and `update_idletasks()` drains idle callbacks, not events — so the window moved/grew after the "atomic present" and Windows blitted the old page's pixels into the new position. `_atomic_ui` now repaints (erase) after applying `_pending_geometry` AND queues an `after(0)` repaint that actually drains the Expose queue. Three supporting fixes: `_on_root_configure` gates its heal on the full GEOMETRY not just size (a swap between two same-height pages is a pure MOVE, which never healed); `_repaint_all` grew an `erase=True` mode because repaint-over cannot clear a newly exposed strip that no widget covers, and now refuses to run with hwnd 0 (`RedrawWindow(NULL)` repaints the DESKTOP); and `_atomic_ui` SKIPS the freeze while the root is unmapped — toggling WM_SETREDRAW clears WS_VISIBLE, and doing that across an in-progress map was the intermittent ghost on the returning-user path, where a fast restore promotes the dashboard microseconds after `deiconify()`. Guarded by `tests/test_session_restore.py::PageSwapHealTests`.

- `2026-08-06` — `tk.OptionMenu` replaced by a house `Dropdown` control (v1.6.47) for the words-range, microphone and popup-position selectors. On Windows OptionMenu posts a NATIVE menu that IGNORES the configured bg/fg, so all three rendered as a white box with a black border against a near-black UI — the colours were being set and silently dropped. `Dropdown` draws the closed control (rounded, chevron, hover) and posts an `overrideredirect` Toplevel with DWM-rounded corners, hover rows, an accent tick on the current value, wheel scrolling and screen clamping for long lists (the mic list runs to ~20 devices). It keeps the StringVar contract, so existing `trace_add` handlers were untouched.

- `2026-08-07` — Home's hint rows are links (v1.6.51): clicking ALT+V / ALT+C / ALT+R (pill, label or the row) opens the Hotkey tab via `_link_to_hotkeys`. Deliberately NO hover fill or colour change — the pill is the design, and a bg swap on a `tk.Label` paints a hard rectangle behind it; the `hand2` cursor is the whole affordance. Panel header re-spaced at the same time (icon and caption share one line, headline figure at `_PANEL_VALUE_Y`), because at 31px on its own row the glyph ran into the "6.6 hrs" below it.

- `2026-08-07` — `Dropdown`'s dismiss binding is now permanent (v1.6.51) instead of bound-on-open/unbound-on-close. Tkinter's `unbind(sequence, funcid)` drops **every** binding for that sequence on Python < 3.12, and **CI builds on 3.11** — so closing a dropdown silently deleted unrelated toplevel `<Button-1>` handlers (it would have eaten the impact panel's dismiss-anywhere). The handler is a no-op while the list is closed, and the control's own click returns `"break"` so the opening click can't reach it.

- `2026-08-10` — Dropdown lists dismiss when the app loses foreground (v1.6.57). The house `Dropdown` list is a `-topmost` `overrideredirect` Toplevel; it already dismissed on Escape and on a click elsewhere INSIDE the app (`_on_toplevel_click`), but nothing closed it when the app itself stopped being the foreground window — so clicking away to another app, minimising, or Alt-Tabbing left the list orphaned on top of whatever the user switched to while the rest of the app went behind it (reported against the popup-position selector; the words-range and microphone selectors are the same class, so all three were affected). Fix: `open()` starts `_watch_foreground()`, a 150ms `after` poll (the same "re-check Win32 state on a timer" pattern as `popup._keep_on_top`) that closes the list the moment `GetForegroundWindow()` is neither the app's real top-level nor the list Toplevel itself. `winfo_id()` is a CHILD window on Windows, so the handle is resolved via `GetAncestor(GA_ROOT)` before comparing (the gotcha `popup._top_hwnd` documents); the list's own Toplevel is included in the "ours" set so activating the overrideredirect window never self-dismisses. `_foreground_is_ours()` fails OPEN — a Win32 hiccup must never close a list the user is mid-read of. `close()` cancels the pending watch. Guarded by `tests/test_dropdown_dismiss.py`.

- `2026-08-31` — The Hotkey tab's shortcut buttons went back to the plain rounded button (v1.6.73). The glass port put the CRM glass button on "Change Hotkey" and Save; Ryan's call is that the glass treatment belongs to the keycaps above them, and two glass slabs stacked in a 161px column read as one. `_hotkey_btn`/`_save_btn_new` now build `SurfaceButton`, a `RoundedButton` subclass that owns its own hover, which fixes two things the old bare hover binds got wrong: `bg=` sets the RESTING fill, so the click that turns "Change Hotkey" into "Cancel" (always made with the pointer ON the button) keeps its red once the pointer leaves; and `command=None` disarms Save rather than `unbind()`, which drops EVERY handler for a sequence on Python < 3.12 while CI builds on 3.11. Labels stay "Change Hotkey", and Save keeps its two faces (grey "Saved" at rest, accent "Save" once armed); the pencil, tick and disk icons go, since the plain button draws text only. Layout is the old shape again: the dictation pairs stack left-aligned at their natural width, the refine pair shares its row. Guarded by the rewritten source-level pins in `tests/test_glass_button.py`. **The keycaps, help dots and card headers from the glass pass all stay** — only the two buttons reverted.

- `2026-09-09` — **Settings got a search bar (v1.6.75).** Thirty-odd cards over six sections is not a page you scroll to find something in. `_section()` now registers its header frame, `_index_settings_search()` snapshots every direct child of the scroll content once the page is built (order, pack options, owning section, and all the text under it), and `_apply_settings_search()` is pure `pack_forget`/`pack` over that index — **nothing is rebuilt**, so no toggle loses its value, no Dropdown loses its StringVar, and the ScrollPane's wheel/scrollregion machinery is untouched. A section header survives only when something under it matches; the section title itself matches everything beneath it. The bar is packed BEFORE the ScrollPane so it takes the top strip and does not scroll away with the content. The whole sweep runs inside `_atomic_ui` — a forget/pack pass over thirty cards paints every intermediate layout otherwise. Guarded by `tests/test_settings_search.py` (behaviour + source-level pins that the builder actually creates the bar and takes the index).

- `2026-09-09` — The voice-training button stopped being cut in half (v1.6.77). Reported with a screenshot reading "Import my past". The status label and the button shared one row, and between them they wanted more width than a ~290px card has, so the button was pushed off the right edge and clipped. They are now stacked — status on its own line, wrapping like every other description on the page, button on the line below — which fits at any window width. `tests/test_phrases_page.py::VoiceCardLayoutTests` measures the real widgets at the real width AND asserts the old side-by-side arrangement genuinely did not fit, so a revert fails there rather than in a screenshot three weeks later.

- `2026-09-21`: **Dashboard tabs are the CRM's connected bookmark tabs, and a Learning tab holds everything the app knows about how you talk (v1.6.81).** `bookmark_tabs.py` ports Brightlink `src/components/BookmarkTabs.tsx` (the `connected` variant) with every shape, glow and colour number verbatim, converted at `REM = 15px`. Tabs are Home, Learning, Hotkey, History (Ryan's order), declared once in `AppWindow._DASH_TABS`; the vocabulary, snippets and phrases pages have no tab of their own, `_TAB_OF_PAGE` keeps Learning lit while they are open, and their Back returns to Learning. The Custom Vocabulary / Snippets / Phrases cards and the Learn My Phrases toggle moved from Settings to Learning (one canonical place; Settings no longer carries them). The strip is ONE image per state (width x current tab x hovered tab), cached, with hover states pre-rendered on idle. **Only the shape masks are supersampled (4x, PIL, box-filtered down); the gradients are computed at 1x** — doing the layer maths at 4x cost 200-670ms a render on Ryan's machine, 1x is ~20ms. Labels stay native canvas text (ClearType). Padding is equal per tab and grows to fill the window, capped at the CRM's 1.35rem; below `MIN_PAD` a tab drops its icon before it drops padding (all four keep icons at `MIN_W`). The Learning glyph is lucide's brain (the CRM's icon set), traced from its SVG by a small path/arc parser in `ui_render`. Settings card helpers became methods (`_page_section`, `_card_glyph`, `_toggle_card`, `_link_card`) so both pages share them. Guarded by `tests/test_bookmark_tabs.py`.

- `2026-09-23`: **Universal search bar + Ask AI, and the refiner keeps existing line breaks (v1.6.87).** Two asks. (1) A single search bar under the header (`_build_universal_search`, spanning the window between the lockup and the tab strip, styled like the app's other `_search_bar`s with an accent "Ask AI" pill on the right, à la the CRM's `Search contacts…` bar). Typing filters a catalogue of every page and setting and jumps straight there: a page result switches tab, a setting result opens Settings filtered to that card by reusing `_apply_settings_search` (no new scroll/highlight machinery). Ask AI (button, or Enter on a question — `app_search.looks_like_question`) sends the query plus the catalogue to the same `AIRefiner` the popup uses, scoped by `app_search.help_prompt` to answer only from the app's real settings/pages in plain prose, and shows the answer with clickable jump chips for any setting it names (`app_search.linked_entries`). Matching/question/prompt logic is the pure, unit-tested `app_search.py`; the catalogue fills itself as the tabs build (each `_toggle_card`/`_link_card`/section registers via `_register_search_setting`, `_cat_location` names the owning tab), topped with the five pages. The results float in a **placed** panel over the content area, never a Toplevel (every Toplevel here has cost a Z-order or DPI bug), anchored with `relwidth=1.0 width=-40` so it lines up with the bar's 20px gutters without depending on a realised pixel width; it hides on tab switch, on resize, and on real focus loss (kept up while an AI answer is showing or the pointer is inside it). (2) The refiner now KEEPS existing line breaks by default: a custom Ask ("make this better") and Fix All (`punctuation`)/`context_fix` no longer flatten a laid-out email back into one line — only the modes that exist to restructure (email/formal/casual/concise/prompt_optimiser) reflow, and a custom instruction may still override in its own words (`ai_refiner.refine`, gated on `"\n" in text`). Guarded by `tests/test_app_search.py`, `tests/test_universal_search.py` (live Tk) and `tests/test_refine_preserve_layout.py`. NB `app_search.help_prompt` names the app via `brand.PRODUCT_NAME`, never a literal, so `tests/test_brand.py` stays green.

- `2026-09-23`: **The search bar became ONE context-aware bar, and its icons are high-res (v1.6.89, iterating on the v1.6.87 bar above).** Ryan's feedback over several rounds. (1) **One bar, no duplicates.** Every page had two search bars (the new top bar plus the page's own History/Settings/Vocabulary/Snippets/Phrases bar). The inline bars are removed; the one top bar retunes per page via `_page_search` (a `{page: {placeholder, filter}}` map each page fills through `_register_page_search`). On a list page it runs in **filter mode** — typing drives that page's own filter in place (the exact `_on_hist_query`/`_apply_settings_search`/`_on_query`/`_render_phrases` callbacks the old bars used) with the page's placeholder ("Search transcriptions…", etc.) and NO jump dropdown; on Home/Learning/Hotkey it runs in **universal mode** (jump catalogue + dropdown). `_switch_dash_tab` calls `_usearch_apply_page(name)` to swap placeholder+mode, clear the field and reset that page's filter to unfiltered. **Ask AI works in every mode** (the button always asks the app-scoped AI). `_focus_setting` (a universal jump to a setting) now drives the top bar, since `_settings_search` is gone. Placeholder is a per-instance `_usearch_placeholder`, not the class constant. (2) **Passive by default.** The bar only shows its accent/active look while it actually has focus. Clicking a Label/Canvas/card never moves focus in Tk, so the entry used to keep focus and stay accent-bordered after you clicked away; `_usearch_click_outside` (bound on root `<Button-1>`) blurs it when a click lands outside the bar/panel and not on another text field. `takefocus=0` keeps it from grabbing focus on Tab or window re-activate. (3) **Type-anywhere** (`_usearch_type_anywhere`, root `<Key>`): start typing on the dashboard and it lands in the bar, guarded so it never steals a key meant for another text field, a Ctrl/Alt shortcut, or hotkey capture. (4) **High-res icons.** The magnifier and the Ask AI star are now crisp PIL glyphs (`ui_render.icon_glyph` "search" and "sparkle", supersampled) instead of a hand-drawn `tk.Canvas` oval and the chunky `✦` font glyph; the field itself is `ui_render.round_rect`. **Standing rule (memory `high-res-icons-always`): every icon/glyph in this app must be PIL-rendered, never a canvas primitive or font glyph, whenever it can be.** The layout is logos → bar → one visible separation line (`C["border"]`) → tabs; the faint header hairline under the lockup was dropped. Guarded by `tests/test_universal_search.py` (mode switching, type-anywhere, outside-click blur, live Tk), with `tests/test_settings_search.py` and `tests/test_library_pages.py` updated to the one-bar contract (`_register_page_search`, no inline `_search_bar`).

- `2026-09-23`: **Settings reordered and re-written, Voice Training moved to Learning, and Create Account files the account properly (v1.6.90).** Six things from one report.
  1. **A fresh account claimed a saving before dictating a word.** `_refresh_impact`'s first bucket was `m < 1 -> "< 1 min"`, which catches exactly zero, so day one read "< 1 min saved / A tiny moment". Zero now reads `0 min / Dictate to start saving`; "< 1 min" still stands for a real sub-minute saving. The **speed card told the same untruth** and is fixed with it: 160 wpm is the modelled figure the savings maths uses, not this person's, so with `total_words == 0` the card reads `-- wpm / Dictate to measure`. The v1.6.70 nominal-160 fallback is untouched for the case it was written for (words exist, window too thin to measure). Pinned in `tests/test_impact_speed.py`, both directions.
  2. **Voice Training moved from the foot of Settings to the foot of Learning** (`_build_voice_training`, called by `_build_learning_tab`). Learning is where everything the app knows about how you talk already lives, and this is the card that decides whether any of it leaves the machine. Learning builds BEFORE Settings and sets `_cat_location` itself, so the universal-search catalogue followed with no extra wiring; the handlers address the widgets by attribute, so none of them changed. The v1.6.77 stacked status/button layout is carried over verbatim and still pinned.
  3. **Settings regrouped.** Updates stays first (Ryan's explicit call). The rest reads Microphone -> Dictation -> Live Typing -> Popup -> Sounds -> Account. The win is splitting the old twelve-card "Dictation" section: it held two unrelated concerns under one heading, how the TEXT comes out and where the PILL sits on screen, so nobody hunting for "keep the pill out of my screen recording" was going to look under Dictation. "Feedback" became **Sounds** (it read as *user* feedback and holds one toggle about audio cues). Order pinned in `tests/test_settings_copy.py`.
  4. **The Save Settings button is gone.** The mic dropdown was the only control on the page that waited for it; every toggle has always applied on touch, so the page asked you to save one setting out of thirty and said nothing about the other twenty-nine. `input_device` has applied live for a long time (`_apply_runtime_setting` re-points the recorder, clears the cached device index, drops the probe's mic memory and restarts the warm stream) -- the "needs a restart" line in section D was simply stale, and is corrected. The dropdown now applies on selection with its own "Saved" confirmation, gated on `_mic_menu_ready`: `_populate_mic_menu` writes to `mic_var` itself while the device list loads, and applying those writes would save a device nobody chose -- worse, a pinned mic that has since been unplugged would silently rewrite the config to auto. A flag, not a first-write counter: when no devices enumerate at all, a counter swallows the user's first real change instead.
  5. **Every card description is one short line saying what ON means.** Mechanism, caveats and bracketed exceptions are gone from ~20 cards across Settings and Learning. One was a live bug rather than length: Sound Feedback claimed a beep when "transcription finishes", and v1.6.51 deliberately made that third cue SILENT -- the copy had been wrong for fifteen releases. `tests/test_settings_copy.py` fails any description over 90 characters, so the next paragraph is caught in CI instead of in a screenshot.
  6. **Sign-in: Google hidden, Create Account made real.** `login_window.GOOGLE_SIGN_IN = False` guards only the PACKING of the divider and the button -- `_sign_in_google`, the localhost callback server and `_exchange_oauth_code` are all still there, so restoring it is the flag and nothing else (pinned, so none of it is deleted as dead code later). Note `_switch` packed the forgot-password link `before=self._divider_frame`, and `pack(before=w)` RAISES when `w` is unpacked; `_link_anchor()` is what keeps that legal. Create Account gained **Your name** (required) and **Company (optional)** with the caption "Leave blank for a personal account", and `auth.sign_up` now sends them as `options.data` -- **omitting a blank key rather than sending ""**, because the shared `handle_new_user` trigger tests `nullif(trim(...), '') IS NULL` to set `is_personal`. That trigger is what names the organisation and decides whether Super Admin lists the person under a company or under Users; sending neither key, as Echo did, filed every account created here as a company-less workspace named after the email prefix. No "it's just me" checkbox (Ryan's call -- the payload is identical either way). **The page is now sized per mode**: signup carries two more fields than login and one fixed height cannot serve both, so `required_height()` reports what the card asks for (measured: login 477, signup 725) through `on_height_change`, which the embedded path routes into `_resize` -- already the deferred-geometry, self-healing path from v1.6.38/v1.6.47. `_CHROME_H` (222) is MEASURED off the real widgets and `tests/test_signup_payload.py` recomputes it, so a layout change that invalidates it fails there rather than as a clipped field.

- `2026-09-23`: **Compact dashboard: default height 680 -> 568 (v1.6.91).** Reported: on the 150% laptop the window filled the screen height, so every drag tripped Snap Layouts. Positioning only, no feature changes. Header 22+22px padding -> 10+10 and the lockup 42 -> 34 (splash and sign-in keep 42); search bar 42 -> 38 with its 12px top gap gone; separator, tab-strip and content gaps 12/12/10 -> 10/8/8; footer padding 10 -> 6; status card 17pt -> 14pt with tighter padding. The range picker and word count moved from their own bar BELOW the impact cards into the "Your impact" heading row ABOVE them (the control that scopes the cards now sits above what it scopes), which removed a whole row. The breakdown panel now replaces the heading row plus the cards (`_impact_head`), so it keeps ~196px, within 8px of before; the heading drops "dictated" from the count when the row is too narrow (`_fit_impact_words`). Saved sizes taller than the new default are clamped once (`config.window_layout_rev`, `_migrate_window_sizes`), and the super admin's clamped size is pushed as the install default. **Trade-off, chosen on purpose:** DASH_H is sized to Home, so the Hotkey tab (418px of content, 367 available) now scrolls its last ~50px on its ScrollPane like Settings and Learning. Fitting it too needs a redesign of its stacked Change/Save pairs, which would reverse the 2026-08-31 call on that tab. `tests/test_glass_button.py` pins the overflow at <= 60px; `tests/test_app_window_sizing.py::HomeFitsDefaultHeightTests` pins that Home fits DASH_H.

- `2026-09-23`: **The v1.6.90 design is back, trimmed, and the super admin sets its spacing (v1.6.93).** Ryan preferred the v1.6.90 look to the v1.6.91 compact one, so `app_window.py` and the three design tests (`test_brand_artwork`, `test_impact_panel`, `test_glass_button`) were restored to v1.6.90 exactly (42px lockup, 17pt status, words bar under the cards) and only the GAPS changed. Measured: the v1.6.90 Home actually needed ~703px and clipped at 680; the dead space was mostly around the logo (22 above, 22 + 12 below). Every vertical gap is now a named value in `_GAP_DEFAULTS` (logo_top 14, logo_search 20, search_line 10, line_tabs 8, tabs_content 8, status_impact 14, impact_cards 6, cards_words 8, footer 8), `DASH_H` 670 is the natural height at those (663 measured + a few px; `HomeFitsDefaultHeightTests` pins both "fits" and "no band over 12px"), and `_natural_dash_h()` moves with the gaps. **Super admin only** (`SUPER_ADMIN_EMAIL`): a "Spacing" link in the footer (hidden for everyone else, refreshed in `_apply_auth_ui`) puts a dashed handle labelled with its px across every gap on screen; drag to change, double-click for the default, "Done" to leave. A change re-packs the one widget that carries the gap and grows or shrinks the window by the same delta, so nothing clips and no band opens. On release it is pushed to `app_settings["dashboard_gaps"]` (JSON); every install fetches that on each dashboard show and mirrors it into `config.dashboard_gaps` so it holds offline, adjusting its own window height by the delta. Never adopted mid-edit. Handles re-place every 250ms while editing, because the rounded cards size themselves asynchronously and a handle placed once drifted off its gap (caught by screenshot). `_grow_window` builds on its own last request, because `winfo_height` lags a `geometry()` call and several changes in one pass each read the same stale height (caught by a scripted drag: 670 -> 673 instead of 667). Layout rev 2 (`_migrate_window_sizes`) raises any saved height below the natural height once, since v1.6.91 clamped everyone to 568 and Home has no ScrollPane. The Hotkey tab scrolls its last few px again, as it did in v1.6.91. Guarded by `tests/test_app_window_sizing.py` (`LayoutMigrationTests`, `DashboardSpacingTests`, `HomeFitsDefaultHeightTests`).
